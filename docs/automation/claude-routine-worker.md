# Governance 2.0 · Claude Code Routine Bridge

This block connects the provider-agnostic worker dispatcher to Claude Code on the web through Anthropic's Routine Fire API.

## Why this bridge exists

Governance must be able to hand a task to Claude Code without requiring Mike to copy and paste the Task Contract into a browser session.

The bridge preserves the same Governance task identity and sends the complete contract to a saved Claude Code Routine.

## Runtime path

```text
Governance
  -> worker dispatcher
  -> Claude worker selected
  -> GitHub Actions workflow_dispatch
  -> claude-routine-worker.mjs
  -> Anthropic Routine Fire API
  -> Claude Code web session
  -> structured receipt in GitHub issue #341
  -> Governance reconciliation
```

## Required repository secrets

- `CLAUDE_ROUTINE_FIRE_URL`
- `CLAUDE_ROUTINE_FIRE_TOKEN`

The URL must be the exact HTTPS fire URL generated by Claude Code for one Routine.
The token is the per-Routine bearer token shown once when the API trigger is created.

Never store either value in Notion, source control, workflow inputs, logs, screenshots, or chat.

## Workflow inputs

`Governance Claude Worker` accepts:

- `task_id`: canonical Governance task identity;
- `task_contract_b64`: base64-encoded Task Contract JSON.

The workflow verifies that the explicit task ID equals `contract.task_id` before dispatch.

## Adapter behavior

The adapter:

- only accepts `https://api.anthropic.com/v1/claude_code/routines/trig_.../fire`;
- sends the official `anthropic-version: 2023-06-01` header;
- preserves the full Task Contract as literal context;
- returns the Claude Code session ID and session URL;
- maps HTTP 429 to `no_capacity`;
- maps 503 to `degraded`;
- maps auth/not-found failures to `disconnected`;
- treats network uncertainty as `uncertain`;
- never retries automatically because the Routine Fire API does not provide an idempotency key.

## Important safety limit

A successful fire proves that Claude Code accepted the task, not that the task completed. Completion is represented separately by a structured receipt and independent evidence reconciliation.

Completion must still be verified from technical evidence such as:

- branch/SHA changes;
- PR state;
- CI;
- checkpoint emitted by the worker;
- Sandbox evidence where applicable.

The completion loop is implemented with a structured worker receipt in GitHub issue #341. Governance matches the receipt by task_id and dispatch_fingerprint, then reconciles the claimed SHA/tests against GitHub and CI evidence.

## Production

This bridge does not authorize production. Selecting Claude Code as a worker does not grant deploy, merge, production database, payment, or secret access.


## Completion receipt

The saved Claude Code Routine should post a non-sensitive completion receipt to GitHub issue #341:

```text
GOVERNANCE_WORKER_RECEIPT_V1
{"task_id":"...","worker_id":"claude-code-web","dispatch_fingerprint":"...","status":"completed","base_sha":"...","current_sha":"...","files_changed":[],"commands_run":[],"tests_passed":[],"blockers":[],"remaining_work":[],"next_action":"Governance verifies GitHub evidence"}
```

The receipt is a coordination signal only. Governance must still reconcile the claimed branch/SHA and tests against GitHub and CI.

### Routine prompt contract

The Claude Code Routine should be configured with these standing instructions:

```text
You are the Claude Code worker for Governance 2.0.

You will receive a Governance Task Contract as run context.

Rules:
- Preserve task_id exactly.
- Verify the declared repository, branch and base_sha before editing.
- Work only within the declared scope and environment.
- Never broaden scope.
- Never merge to main or deploy production unless the Task Contract contains explicit production authorization.
- Never expose secrets or production data.
- Run the applicable checks.
- If the remote branch no longer matches base_sha, stop and return BLOCKED.
- At completion, push only the authorized branch/PR changes and post one non-sensitive completion receipt to GitHub issue #341 using marker GOVERNANCE_WORKER_RECEIPT_V1.
- The receipt JSON must include task_id, worker_id, dispatch_fingerprint, status, base_sha, current_sha, files_changed, commands_run, tests_passed, blockers, remaining_work and next_action.
- Do not treat the receipt itself as proof; Governance will verify GitHub/CI separately.
```

The Routine needs repository access to `mikevazquez/Demeter`. The API trigger token is scoped to that Routine and must remain only in GitHub Actions secrets.
