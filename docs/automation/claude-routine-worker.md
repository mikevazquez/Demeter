# Governance 2.0 · Claude Code Routine Bridge

This block connects the provider-agnostic worker dispatcher to Claude Code on the web through Anthropic's Routine Fire API.

## Why this bridge exists

Governance must be able to hand a task to Claude Code without requiring Mike to copy and paste the Task Contract into a browser session.

The bridge preserves the same Governance task identity and sends the complete contract to a saved Claude Code Routine.

## Runtime path

```text
Governance
  -> worker dispatcher
  -> Claude worker selected
  -> GitHub Actions workflow_dispatch
  -> claude-routine-worker.mjs
  -> Anthropic Routine Fire API
  -> Claude Code web session
```

## Required repository secrets

- `CLAUDE_ROUTINE_FIRE_URL`
- `CLAUDE_ROUTINE_FIRE_TOKEN`

The URL must be the exact HTTPS fire URL generated by Claude Code for one Routine.
The token is the per-Routine bearer token shown once when the API trigger is created.

Never store either value in Notion, source control, workflow inputs, logs, screenshots, or chat.

## Workflow inputs

`Governance Claude Worker` accepts:

- `task_id`: canonical Governance task identity;
- `task_contract_b64`: base64-encoded Task Contract JSON.

The workflow verifies that the explicit task ID equals `contract.task_id` before dispatch.

## Adapter behavior

The adapter:

- only accepts `https://api.anthropic.com/v1/claude_code/routines/trig_.../fire`;
- sends the official `anthropic-version: 2023-06-01` header;
- preserves the full Task Contract as literal context;
- returns the Claude Code session ID and session URL;
- maps HTTP 429 to `no_capacity`;
- maps 503 to `degraded`;
- maps auth/not-found failures to `disconnected`;
- treats network uncertainty as `uncertain`;
- never retries automatically because the Routine Fire API does not provide an idempotency key.

## Important safety limit

A successful fire proves that Claude Code accepted the task, not that the task completed.

Completion must still be verified from technical evidence such as:

- branch/SHA changes;
- PR state;
- CI;
- checkpoint emitted by the worker;
- Sandbox evidence where applicable.

The next increment must add a durable completion callback or observable checkpoint so Governance can close the loop without relying on a human to inspect the Claude session.

## Production

This bridge does not authorize production. Selecting Claude Code as a worker does not grant deploy, merge, production database, payment, or secret access.
