# Studio Flow V2 — Hoy

Estado: implementación Sandbox / UAT pendiente.

## Principios
- Hoy es una pantalla operativa, no un dashboard de reportes.
- Mostrar primero las sesiones y lo que requiere acción.
- Las acciones viven junto al objeto que modifican.
- Menos botones visibles; acciones secundarias bajo demanda.
- Cerrar una sesión consolida el estado, pero no bloquea al estudio.
- Las correcciones posteriores conservan trazabilidad y requieren motivo cuando cambian asistencia ya cerrada.

## Agregar alumna
1. Abrir la sesión.
2. Agregar alumna desde la propia sesión.
3. Buscar primero entre alumnas existentes.
4. Si no existe, crearla sin abandonar la sesión.
5. Mantener el flujo disponible después del cierre para personal autorizado.

## Asistencia
- Durante la clase: Asistió / No asistió inline.
- Después del cierre: resultado consolidado.
- Una modificación posterior se trata como corrección y solicita motivo.
- Nunca se elimina el histórico de reserva/no-show.

## Densidad
- KPIs son secundarios frente a sesiones.
- Detalles y acciones infrecuentes no compiten con la operación principal.
- Mobile-first: agregar alumna y asistencia deben quedar cerca del contexto.
